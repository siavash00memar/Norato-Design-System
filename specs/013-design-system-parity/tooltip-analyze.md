# Tooltip — Analyze

## Evidence
- design reference Tooltip route (`design reference) inspected live on 2026-11-08: 16 variants = Dark/Glass × Simple/Rich × Top/Bottom/Right/Left; reference default is a dark compact bubble above an icon-only trigger. RTL collapsed sidebar opens left.
- design reference anatomy is bubble, short text, arrow; keyboard focus must open it; focus ring is 2px outside the trigger. Essential content should not live only in Tooltip; avoid stacking.
- Installed Reka UI exposes TooltipProvider/Root/Trigger/Portal/Content/Arrow. Provider delay defaults 700ms, skip delay 300ms, and supports ignoreNonKeyboardFocus, disableHoverableContent, disabled. Root supports controlled `open`/`update:open`, `defaultOpen`, per-tooltip delay and disabled. Content inherits Popper placement/collision properties and handles Escape; primitive supplies accessible description relationship.
- Existing `.sample-tooltip` rules use raw dimensionless tokens for a generic dark bubble and lack a Button-sized preview frame, adapter, playground or execution API. No Tooltip-specific semantic tokens exist. Use existing radius, spacing, inverse surface, text, shadow, focus tokens; arrow uses the same surface.
- Reka Tooltip is the correct primitive; no package addition needed.

## Decision and risk
- Reconcile design reference's Rich visual action with Tooltip semantics: tooltip content must not become a focusable/action region because ARIA tooltip patterns cannot receive focus. Treat any displayed action label as noninteractive context; actual actions remain on the trigger/host. If a future true action is required, use Popover instead.
- Accept a trigger slot as the adaptable child, plus a Playground button trigger. Preserve consumer's semantic trigger and keyboard target; do not create a hidden duplicate.
- Full matrix and responsive interaction were executed in the browser on 2026-11-08. design reference and Norato were compared at 1265×720: design reference preview frame is approximately 628×294px and Norato approximately 578×286px, so their widths are not identical despite matching composition. Matrix: all 16 Dark/Glass × Simple/Rich × Top/Bottom/Right/Left combinations rendered within viewport, in RTL, without observed stretching; arrows measured 10×5px for horizontal placement and 5×10px for vertical placement. Rich Top flipped to Bottom when viewport space was insufficient. At 390px and 320px there was no horizontal document overflow; at 320px Rich Right flipped to Left and remained visible alongside its 48×48 target. Real keyboard focus opened the tooltip; Escape closed it while retaining focus, with a 2px yellow outer focus ring. The live pointer check remained closed at 100ms, opened as `delayed-open` by 550ms, and closed after pointer exit. Follow-up analysis found each adapter had an isolated provider, which prevented sibling skip-delay sharing; `NoratoTooltipProvider` now supplies a shared scope and a two-trigger playground fixture. Timing between sibling triggers still lacks reliable pointer-only evidence. Independent screen-reader review is also outstanding; DoD stays open.
