# Norato Spec-Driven Error Log

این فایل برای ثبت خطاها، انحراف‌ها، علت ریشه‌ای و اقدام پیشگیرانه نگهداری می‌شود.
قبل از هر مرحله باید خطاهای مرتبط بررسی شوند و بعد از هر خطای مهم، این فایل به‌روزرسانی شود.

## قواعد استفاده

- هیچ خطایی نباید فقط در گفت‌وگو باقی بماند؛ خطاهای مؤثر بر فرایند باید ثبت شوند.
- هر ورودی باید شامل علت ریشه‌ای و اقدام پیشگیرانه باشد.
- تکرار یک خطا باید در مرحله Analyze به‌عنوان مغایرت فرایندی گزارش شود.
- این فایل جایگزین اصلاح artifact اصلی نیست؛ اصلاح باید در سند مربوطه نیز انجام شود.

## خطاهای ثبت‌شده

### ERR-001 — استخراج Design Context فیگما بدون انتخاب لایه

- **تاریخ:** 2026-08-23
- **مرحله:** Specify / Discovery
- **شرح:** فراخوانی استخراج context فیگما با وجود داشتن `fileKey` و `nodeId`، به‌دلیل انتخاب‌نشدن هیچ لایه‌ای در محیط فیگما ناموفق شد.
- **علت ریشه‌ای:** ابزار فیگما در این محیط به selection فعال وابسته است و شناسه‌ی نود به‌تنهایی کافی نیست.
- **اثر:** استخراج دقیق جزئیات بصری و قرارداد لایه‌ها انجام نشد؛ فقط metadata قابل دریافت بود.
- **اقدام اصلاحی:** قبل از اجرای استخراج context، انتخاب فریم یا کامپوننت هدف در فیگما الزامی شد.
- **اقدام پیشگیرانه:** در Specify ابتدا selection و context معتبر می‌شود، سپس توکن‌ها و قرارداد کامپوننت‌ها استخراج می‌شوند؛ در صورت شکست، کدنویسی آغاز نمی‌شود.
- **وضعیت:** بسته — در اجرای بعدی، نود `8772:1368` به‌صورت معتبر انتخاب و context از لایه‌های داخلی استخراج شد.

## الگوی ثبت خطای جدید

### ERR-002 — قرارگیری اشتباه سایدبار در RTL

- **تاریخ:** 2026-08-23
- **مرحله:** Implement / Visual QA
- **شرح:** سایدبار به‌جای سمت راست در سمت چپ نمایش داده شد.
- **علت ریشه‌ای:** استفاده از `inline-end` در RTL که به لبهٔ چپ اشاره می‌کند.
- **اثر:** مغایرت با معماری ناوبری و انتظار بصری کاربر.
- **اقدام اصلاحی:** جایگزینی منطقی با `inline-start` و اصلاح حاشیه و فضای محتوای اصلی.
- **اقدام پیشگیرانه:** بررسی visual direction در هر breakpoint و تست دستی RTL پیش از تحویل.
- **وضعیت:** بسته

### ERR-003 — نبودن گیت Visual QA برای preview کامپوننت‌ها

- **تاریخ:** 2026-08-23
- **مرحله:** Analyze / Visual QA
- **شرح:** نمونه‌های واقعی Figma به preview اضافه شدند اما محدودیت overflow و breakpoint در checklist به‌صورت صریح gate نشده بود و layout به‌هم‌ریخته شد.
- **علت ریشه‌ای:** اعتبارسنجی فقط TypeScript، token و inventory را پوشش می‌داد.
- **اثر:** صفحهٔ Components در بعضی عرض‌ها دچار فشردگی و ناسازگاری بصری شد.
- **اقدام اصلاحی:** محدودکردن کارت‌ها، جلوگیری از overflow، تنظیم grid سه‌ستونه و تعریف breakpointهای Visual QA.
- **اقدام پیشگیرانه:** پیش از هر تحویل UI، screenshot/visual review در 1440، 1024، 768 و 390 پیکسل الزامی است.
- **وضعیت:** بسته
